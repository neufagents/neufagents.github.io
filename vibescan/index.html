What we look for

  • API keys and tokens hardcoded in source
  • .env files committed — or served publicly
  • Supabase / API service-role keys exposed in the browser
  • Database tables readable or writable without auth (RLS off)
  • Dependencies with known vulnerabilities
  • Secrets or internal IDs leaking into client bundles
  • Webhook handlers without signature verification
  • Auth enforced only on the frontend
  • Admin or debug endpoints left open
  • Storage buckets left public

How it works

  1. You send a repo link (public by default — no write access needed, ever).
  2. We run our scanner (static checks, tuned against false positives) plus a manual pass.
  3. You get a report grouped by severity, with file, line, and the fix.
